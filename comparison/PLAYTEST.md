# 実機で操作感を評価する

自作版の基本キーボード動作は2026-10-04に確認した。人による好み・実パッドの感度・入力から表示までの遅延は未測定。
以下は実際に参加者が遊んで記録する手順であり、回答の例や架空の評価は集計へ入れない。

## 同じ端末・同じ操作デバイスで比べる

比較対象は共通射撃場の自作版とUnity版。現状は自作DX12/Unity D3D11なので、APIが異なる探索的プレイ評価と明記する。
保護の影響だけを調べる回は通常の自作版と保護版を比較し、同一DX12で揃える。異なる目的の結果を混ぜない。

1. PC、GPU/ドライバー、モニターHz、ゲームexeのSHA256、デバイス名と接続方法、ゲーム感度を記録する。
2. 参加者にはA/Bだけを表示。対応表は進行役が持つ。奇数の参加者はA→B、偶数はB→Aとする。
3. 初めに各版1回練習。左右スティック/マウス、発砲、やり直し、終了が動くかを実機で確認する。
4. 各版で60秒の射撃場を3回ずつ遊ぶ。10的クリア時は残り時間も記録する。途中の設定変更は別試行扱い。
5. 各版の直後、反応のよさ・引っ掛かりの少なさ・狙いやすさ・再度遊びたい度を1〜5で答えてもらう。
6. 機械的な不具合と主観的な好みを分けて記録する。最後に改善してほしい点を自由記述する。

参加者IDは個人名を避け、まず8〜12人を目安にする。経験差を「FPSをほぼ遊ばない/時々/頻繁」で記録する。
実パッド評価は接続方式ごとに記録し、キーボード/マウスの結果と合算しない。
各版を終えた直後の評価を残し、欠測は空欄のままにする。

| 記録欄 | 内容 |
|---|---|
| 試験ID / 参加者ID / 日時 | 再識別のための記録 |
| 比較目的 / AとBの対応 / 遊ぶ順序 | エンジン比較か、保護有無比較か |
| PC / exe SHA256 / デバイス | 同一条件を確認 |
| 各版の3回の命中数とクリア時間 | 未クリアは時間を空欄、命中数は残す |
| 各版の4項目の1〜5評価 | 高い方が良いと統一 |
| 切断・無反応・視点ドリフト・フリーズ | 発生時の操作とログ |
| 自由記述 | 操作しづらいところ、もう一度遊びたい理由 |

## 入力から表示までの時間は外部で測る

フレームCSVから入力遅延を算出しない。入力接点/表示を同時に記録できる測定器、または入力動作と画面が同時に映る
高速度カメラで、押下から最初の見た目の変化までを繰り返し測る。カメラfpsと判定誤差も併記する。
目視で「軽い」と感じた評価をmsへ換算しない。今回、カメラや実パッドが利用できていないため、この項目は未実施。

## 集計

参加者数と欠測数を示し、同じ人のA/B差を比較する。AB/BA順で傾向が変わるか、操作経験で偏るかを確認する。
中央値と分布、自由記述を一緒に示す。小人数の好みをエンジン一般の性能優位の証明にはしない。
不具合修正で操作を変えた場合は、同じ版を使った参加者の結果だけで比較し直す。
